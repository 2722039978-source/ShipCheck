# ShipCheck 交付检查扩展

用户已经批准实施文件内容检查、修正尝试、交付报告与历史查询、工单模板和编辑、依赖与迁移检查。

## 行为

1. 兼容现有 JSON 工单，增加逐文件 SHA-256、字节数、允许空文件，以及允许目录、禁止路径规则、清单之外文件策略。预期摘要由发布者提供。完整读取 ZIP 文件并核对内容，检查全部条目的路径和重复名称。
2. 失败记录可以创建修正尝试，选择新输入或新命令。原工单及原记录保持原样。每次尝试保存独立输入、命令、日志、产物、来源和比较结果。比较已解决、持续存在、新增问题，以及输入与 ZIP 内容变化。
3. verify、run、replay、revise 均保存工单、验收 JSON、带时间与工具版本的记录，以及可离线打开的 HTML 报告。报告包含 ZIP SHA-256，保存实际验收的 ZIP。历史查询支持工单号、版本、日期和状态，能够打开报告、产物和证据。
4. 模板保存名称、版本、完整工单规则和打包默认值。创建工单保存模板来源及完整规则快照。窗口支持编辑工单基本信息和完整 JSON 规则，读取、校验、保存工单，读取和保存模板，并把工单用于验收或打包。命令行提供对应操作。
5. 工单可声明组件及预期版本、依赖组件及允许版本、迁移步骤及顺序。包内 release.json 声明实际组件及迁移步骤。验证声明与工单一致、依赖条件满足、迁移连续到达目标版本、关联文件存在。报告明确展示检查范围，试装验证由目标环境承担。

## 使用方式

Windows 原生窗口增加工单和历史页面，复跑页面提供修正输入与修正命令。报告区域保持可复制文本，提供打开 HTML 报告和结果目录的按钮。所有业务处理与 CLI 共用。

## 验证要求

使用真实 ZIP、文件和本机 tar.exe 验证正常交付、错误摘要、空文件、额外文件、依赖冲突、迁移缺项、失败后修正、历史过滤、模板复制及原记录保持原样。测试产生的内容位于 .local 内。窗口通过原生控件的文本与事件检查，不使用图像识别。CLI 与图形程序都必须成功构建。
